# Audio ownership and sample clock

One control producer and one audio consumer share two bounded single-producer, single-consumer rings for events and traces. A third ring can capture rendered stereo samples. The rings publish a slot with a release store and consume it after an acquire load. Full rings reject the next record and increment separate counters. Event timestamps are unsigned absolute output frame numbers. Ties retain insertion order. The end of a callback belongs to the next block. Already-late events apply at offset zero and are counted. Each callback consumes at most 128 events. Excess eligible events remain queued, and the trace reports that the budget was reached.

A control thread creates, verifies and preallocates a package. It publishes through a one-item mailbox. Replacing an unconsumed package destroys that superseded package on the control thread. The audio thread acquires a new package at the start of a callback when the previous transition and retirement are clear. It mixes both programs over 128 samples, then puts the previous pointer into the retirement mailbox. Control reclamation acquires that pointer after the last audio access. Application teardown stops the callback before engine destruction.

The control thread computes a migration plan against the observed generation. Matching state keys, opcodes, extents and rates permit copying up to 2,048 declared state words. Larger state starts reset. Parameter ramps and compatible active voices carry over. If the active generation changes before activation, the plan is discarded and the engine reports a migration miss. The crossfade still takes place. The visible program metadata is immutable and only the single control thread destroys packages. The callback never owns a refcounted pointer.

Callback-visible atomics have compile-time lock-free checks. DSP state, event queues, scratch registers, crossfade storage and capture rings are allocated before playback. The callback can take an OS monotonic timestamp. Duration traces measure engine execution and capture through the completed clock store. They exclude trace-ring publication and host adapter entry and exit. Measured callback deadlines depend on OS and device scheduling.
